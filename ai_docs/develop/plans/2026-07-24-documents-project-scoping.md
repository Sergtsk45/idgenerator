# План: Разделение документов на проектные и глобальные (scoping по объекту)

**Создан:** 2026-07-24
**Статус:** 🔵 Планирование (реализация не начата)
**Приоритет:** Высокий

---

## Цель

Сделать так, чтобы на экране документов текущего объекта были видны **только его проектные документы + все глобальные**, а не весь реестр. Дать пользователю понятный интерфейс с тремя режимами просмотра (**Проект / Глобальные / Все**) и полным набором действий (создание, редактирование, удаление) прямо в реестре.

## Контекст

### Текущее поведение (проблема)
- Таблица `documents` **не привязана к объекту**: «проектность» определяется только через `document_bindings`.
- `GET /api/documents` (`server/storage.ts::searchDocuments`) отдаёт **весь реестр** без фильтра по объекту.
- Поле `scope` (`project`/`global`) — просто метка, на выдачу не влияет.
- Итог: в новом объекте видны «чужие» документы старых объектов.

### Принятые решения (согласованы с заказчиком)
1. **Модель:** добавляем `object_id` в `documents` (источник истины на уровне записи).
2. **Связь с глобальными:** Вариант 1 «Ссылка» — глобальный документ привязывается к материалам любого объекта без копирования (один документ → много bindings).
3. **UI:** три сегмента — **Проект / Глобальные / Все** (в режиме «Все» карточки помечаются бейджем `Проект` / `Глобальный`).
4. **Осиротевшие `project`-документы** без bindings при backfill: **soft-delete** (`deleted_at = now()`).
5. **Права на глобальные документы:** редактировать/удалять/менять scope может **любой владелец** (без ограничения ролью/создателем).
6. **Счётчик «Документы качества»** на `/source-data`: **учитывает** проектные текущего объекта **+ глобальные**.
7. **Действие «Сделать глобальным»:** **доступно всем** пользователям.

### Правило видимости
```
показываем документы, где deleted_at IS NULL И (
  scope = 'global'                                  -- глобальные видны везде
  OR object_id = :currentObjectId                   -- проектные только в своём объекте
)
```

---

## Архитектурные изменения (кратко)

- `documents.object_id integer NULL references objects(id) on delete cascade`
  - `scope='project'` ⇒ `object_id = <объект>` (NOT NULL по смыслу)
  - `scope='global'` ⇒ `object_id = NULL`
- Согласованность гарантируется CHECK-ограничением:
  `(scope='global' AND object_id IS NULL) OR (scope='project' AND object_id IS NOT NULL)`
- `searchDocuments` принимает `objectId` и `viewMode` (`project|global|all`).
- Глобальные удаляются только если не используются в актах (уже есть `act_document_attachments ON DELETE RESTRICT`).

- Реестр поддерживает 3 режима с бейджами и действиями create/edit/delete/setScope.
- Глобальный нельзя удалить, пока используется в актах (понятная ошибка).
- Миграция безопасна, данные сохранены; тесты и `npm run check` зелёные.
- Документация (`project.md`, `changelog.md`, `tasktracker.md`) обновлена.
