## 1. Синхронизация трёх слоёв

- [ ] `migrations/NNNN_*.sql` — сама миграция
- [ ] `shared/schema.ts` — Drizzle-схема соответствует SQL
- [ ] `shared/routes.ts` — Zod-валидаторы обновлены (insert/patch схемы)
- [ ] `server/storage.ts` — CRUD учитывает новые поля

## 2. Типы и именование

- [ ] Таблицы/колонки `snake_case`; в TS `camelCase` (Drizzle маппит)
- [ ] PK: `GENERATED BY DEFAULT AS IDENTITY` (UUIDv7 только по необходимости, не random v4)
- [ ] Внешние ID (Telegram) — `text`
- [ ] Дробные по доменам: часы `numeric(12,2)`, площади `numeric(14,2)`, объёмы/массы `numeric(14,3)`
- [ ] Дата — `date`; время — `timestamptz` (UTC)
- [ ] Статусы: `text + CHECK(status IN (...))` + Zod enum в коде

## 3. Ограничения и целостность

- [ ] `NOT NULL` / `DEFAULT` / смысловые `CHECK` / `UNIQUE` указаны осознанно
- [ ] Каждый FK — с явной политикой `ON DELETE RESTRICT / CASCADE / SET NULL`
- [ ] `CASCADE` только «вниз по ownership» (дочерняя сущность не живёт без родителя)
- [ ] Для внешних источников (импорт Excel/PDF) — idempotency/dedup ограничения
- [ ] Soft delete: уникальные индексы частичные `WHERE deleted_at IS NULL`

## 4. Аудитные поля (обязательны для бизнес-таблиц)

- [ ] `created_at timestamptz not null default now()`
- [ ] `updated_at timestamptz not null default now()` + триггер `set_updated_at()`
- [ ] В коде `updated_at` руками НЕ обновляется

## 5. Индексы и производительность

- [ ] Индексы под новые запросы добавлены в этой же миграции
- [ ] Partial indexes для «горячих» значений статусов
- [ ] На больших таблицах: нет long-lock операций (`ALTER ... NOT NULL` без backfill, тяжёлый `UPDATE` без батчей)

## 6. Безопасность миграции (add → backfill → tighten)

- [ ] Новая колонка сначала nullable/с default → backfill → потом ужесточение
- [ ] Миграция обратно-совместима со старым кодом на время деплоя (или деплой атомарный и это отмечено)
- [ ] Нет `DROP` колонок/таблиц, на которые ещё ссылается код или прошлые миграции (FK-история: см. баг с `works`/`acts` в 0000)
- [ ] JSONB не используется для фильтруемых/сортируемых полей и ключей связей

## 7. Проверка данных

- [ ] Backfill корректен на реальных данных (спот-чек: пара записей до/после)
- [ ] Smoke затронутых потоков: импорт ВОР/сметы, график, generate-acts, материалы

## Вердикт

**Blocker**: миграция падает на чистой/текущей БД, потеря данных, FK без политики, long-lock на prod-таблице · **Major**: рассинхрон `schema.ts`/SQL/Zod, нет индексов под новые запросы, ручной `updated_at` · **Minor/Nit**: naming, отсутствие CHECK, комментарии
