# Правило импорта позиций из RTF ПК РИК

## 1. Что считается позицией

Импорт создаёт два типа записей `estimate_positions`:

1. **Основная позиция работ** — верхнеуровневая строка с целым `№ п/п`.
2. **Вспомогательная материальная подстрока** — вложенная строка с дробным `№ п/п` (`3.1`, `17.2`), которая относится к последней основной позиции и должна отображаться в графике работ как подстрока.

Основная позиция начинается только с верхнеуровневой строки табличной части, в которой:

1. в колонке `№ п/п` находится целое положительное число;
2. строка содержит `Обоснование`, `Наименование работ и затрат`, `Единицу измерения` и количество;
3. это не повторная строка заголовка с номерами колонок `1 … 13`;
4. блок завершается строкой `Всего по позиции`.

`lineNo` всегда берётся **из второй колонки `№ п/п`**. Первая колонка `номер` служебная и в модель не сохраняется.

Важно: в трёх эталонах верхнеуровневые значения `номер` и `№ п/п` совпадают, поэтому только эти файлы не обнаружат ошибку выбора колонки. Нужен отдельный синтетический тест, где, например, `номер = 9001`, а `№ п/п = 7`; ожидается `lineNo = 7`.

## 2. Код не определяет тип строки

Нельзя считать позицией только строки с кодом `ГЭСН`.

В смете `02-01-05` верхнеуровневыми позициями являются также:

- позиция 2: `65.1.01.01-1119` — счётчик воды;
- позиция 5: `18.1.09.06-0023` — кран шаровой;
- позиция 20: код `ТЦ_...` — счётчик импульсов-регистратор.

Решающим для основной позиции является положение строки и целый `№ п/п`, а не префикс кода.

Вспомогательная материальная подстрока импортируется как `estimate_positions`, если:

1. первая колонка `номер` пустая;
2. в колонке `№ п/п` находится дробный номер вида `N.M`;
3. строка содержит код, наименование, единицу измерения и количество;
4. строка не является коэффициентом, НР/СП, ФОТ, итогом или группой затрат.

Такие строки нужны не для создания задач графика, а для раскрываемых подстрок под основной задачей. Примеры:

- `3.1 / 23.5.02.02-0055 / Трубы стальные электросварные...`
- `6.1 / 23.3.06.02-0006 / Трубы стальные сварные оцинкованные...`
- `17.2 / 23.1.02.06-0034 / Хомуты металлические оцинкованные...`

## 3. Что не является позицией

| Тип строки | Признак | Пример |
|---|---|---|
| Обычный ресурс нормы | обе первые колонки пустые, код ресурса находится в `Обосновании` | `91.14.02-001 / Автомобили бортовые...` |
| Трудовой ресурс | обе первые колонки пустые | `1-100-35 / Средний разряд работы 3,5` |
| Коэффициент | нет целого/дробного `№ п/п` материальной строки, строка часто имеет объединённые ячейки | `421/пр_2020_п.58_пп.б` |
| Группа затрат | служебные обозначения внутри блока | `1 ОТ`, `2 ЭМ`, `4 М`, `ОТм(ЗТм)` |
| Промежуточный итог | нет целого `№ п/п` | `Итого прямые затраты`, `ФОТ` |
| НР/СП | коды `Пр/812...` и `Пр/774...` | `НР Трубопроводы внутренние`, `СП Трубопроводы внутренние` |
| Завершение позиции | имя строки равно `Всего по позиции` | используется как конец блока, но не импортируется |
| Итоги раздела/сметы | нет целого `№ п/п` | `Итого по разделу`, `ИТОГИ ПО СМЕТЕ`, `ВСЕГО по смете`, `Справочно` |
| Заголовок раздела | объединённая строка без целого `№ п/п` | `Раздел 1...`, `Строительные работы` |

## 4. Разделы и подразделы

Раздел определяется последним заголовком перед позицией:

- строка на все 13 колонок с текстом `Раздел ...` — раздел первого уровня;
- строка с двумя пустыми начальными ячейками и названием, растянутым на оставшиеся 11 колонок, — подраздел;
- если документ начинается с такого ненумерованного заголовка до любого `Раздел ...`, он считается разделом первого уровня. Пример: `Водомерный узел ХВС ниже отм. 0,000`.

Полная ожидаемая иерархия и диапазоны `lineNo` находятся в `rik_rtf_golden_contract.json`.

## 5. Эталонные количества

| Файл | Номер сметы | Точное название из документа | Основные позиции | Материальные подстроки | Всего `estimate_positions` |
|---|---:|---|---:|---:|---:|
| `02-01-02 Ремонт системы отопления.rtf` | `02-01-02` | `Ремонт системы отопления` | 43 | 32 | 75 |
| `02-01-04 Ремонт системы водоснабжения.rtf` | `02-01-04` | `Ремонт системы водоснабжения` | 48 | 77 | 125 |
| `02-01-05 Водомерный узел.rtf` | `02-01-05` | `Водомерый узел` | 37 | 30 | 67 |

В третьем документе исходный заголовок содержит написание `Водомерый узел` без второй буквы «н». Контракт сохраняет исходное значение и не исправляет его по имени файла.

Для каждого файла количество строк `Всего по позиции` совпадает с количеством **основных** позиций: `43 / 48 / 37`.

## 6. Минимальные проверки теста парсера

Тест для каждого эталона должен проверять одновременно:

1. номер сметы;
2. точное название;
3. полную последовательность разделов и подразделов;
4. точное количество основных позиций и материальных подстрок;
5. непрерывный диапазон основных `lineNo` от 1 до последнего номера;
6. контрольные позиции из начала, середины и конца: `lineNo`, код, название, единица, количество и сумма из `Всего по позиции`;
7. отсутствие среди импортированных строк ресурсов, коэффициентов, НР/СП, ФОТ и итогов;
8. совпадение числа основных позиций с числом маркеров `Всего по позиции`;
9. наличие материальных подстрок из контрольных примеров (`3.1`, `6.1`, `17.1`, `17.2`) и отсутствие коэффициентов `421/пр...` среди подстрок.

## 7. Отдельный тест служебной колонки

Три эталона подтверждают структуру, но не различают значения двух первых колонок. Для защиты от регрессии нужен маленький синтетический пример:

- `номер = 9001`;
- `№ п/п = 7`;
- вспомогательная материальная подстрока: первая колонка пустая, `№ п/п = 7.1`;
- ожидается одна основная импортированная позиция с `lineNo = 7`;
- `9001` не должен попасть в `lineNo`, а `7.1` может импортироваться как вспомогательная подстрока.
