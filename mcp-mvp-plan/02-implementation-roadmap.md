# Дорожная карта реализации первого MVP

## Фаза 0. Подготовка

### Результат

Зафиксированы границы MVP, архитектура и тестовый эталон сметы.

### Работы

- утвердить сценарий;
- выбрать тестовый XLSX;
- зафиксировать ожидаемые основные работы и ресурсы;
- добавить/актуализировать `AGENTS.md`;
- проверить миграционный процесс;
- определить dev/stage URL MCP.

### Gate

Нет разработки до утверждения формулы планирования и политики документов.

## Фаза 1. MCP-платформа

### Задачи

- TASK-001: MCP transport и auth;
- TASK-002: workflow state;
- TASK-003: upload sessions и импорт сметы.

### Результат

Агент может подключиться, создать workflow, загрузить смету и получить сохранённый статус.

### Gate

- JWT ownership test;
- idempotency test;
- повторное подключение сохраняет workflow.

## Фаза 2. Анализ и график

### Задачи

- TASK-004: анализ сметы;
- TASK-005: missing-input engine;
- TASK-006: schedule planner.

### Результат

Агент получает формальные вопросы, сохраняет ответы, рассчитывает и утверждает график.

### Gate

- ни один срок не рассчитан без доступных оснований;
- одинаковые входы дают одинаковый draft;
- утверждение создаёт корректные `schedule_tasks`.

## Фаза 3. Материалы и документы

### Задачи

- TASK-007: реестр материалов и requirements;
- TASK-008: загрузка/привязка документов.

### Результат

Пользователь видит материалы, оборудование и отсутствующие сертификаты/паспорта.

### Gate

- чужой документ нельзя привязать;
- один upload не создаёт дубли при retry;
- readiness обновляется после загрузки.

## Фаза 4. Акты и журнал

### Задачи

- TASK-009: readiness и генерация актов;
- TASK-010: журнал и итоговый пакет.

### Результат

Система формирует черновики актов, приложения, журнал и manifest.

### Gate

- финальный package блокируется при критичных missing issues;
- плановые записи журнала не помечаются фактическими;
- generated files принадлежат объекту пользователя.

## Фаза 5. Агентский контракт и эксплуатация

### Задачи

- TASK-011: prompt/resource contract и E2E;
- TASK-012: security, observability, rollout.

### Результат

Сценарий воспроизводится через целевой MCP-клиент, логируется и безопасно разворачивается.

## Рекомендуемый размер PR

Каждая TASK должна укладываться в:

- один логический результат;
- несколько сотен строк production-кода;
- отдельные миграции при необходимости;
- обязательные тесты;
- один draft PR.

Если задача становится существенно больше, агент обязан сначала предложить декомпозицию и не начинать массовый рефакторинг без согласования.
